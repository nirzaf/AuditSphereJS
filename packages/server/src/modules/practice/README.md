# Practice
Purpose: own the practice domain described in the architecture plan.
Owned use cases: firm chart, date-only periods, policy-gated balanced journals, immutable posting, exact reversals, period closure and firm trial-balance query; classified office rent/facility, salary, benefits/end-of-service, overhead, petty-cash and partner-withdrawal journal drafts through explicit firm accounts, with posting delegated to the canonical journal gate; immutable expense classification metadata; separately posted expense-liability settlements; firm-private, scanned, immutable expense receipt versions; canonical firm-numbered engagement invoices with accepted-contract/fee snapshots and immutable lines, atomic deferred-fee recognition in the firm ledger, recorded payments, paid-state, one official receipt, and reasoned voids of unpaid invoices that reverse the invoice journal; pure contract-contribution calculation; effective-dated QAR charge-out rate cards, separate staff-grade assignments, and immutable time-entry charge-out snapshots. Payment allocation/cash postings for invoices, credit notes, AR aging and time-entry correction/approval workflows remain pending; time workflows are owned by T140/T141.
Owned tables: FirmRepository, PracticeAccount, PracticePeriod, FirmPostingPolicy, PracticeJournal, PracticeJournalLine, PracticeExpense, PracticeExpenseSettlement, PracticeExpenseReceipt, PracticeExpenseReceiptUploadSession, EngagementInvoice, EngagementInvoiceLine, InvoiceLedgerPosting, InvoiceNumberSequence, InvoicePayment, InvoiceReceipt, InvoiceVoid, PracticeRateCard, PracticeStaffGradeAssignment, PracticeTimeEntry.
Public services: createPracticeAccount, createPracticePeriod, approveFirmPostingPolicy, createPracticeJournal, createPracticeExpenseDraft, attachPracticeExpenseReceipt, listPracticeExpenseReceipts, sweepPracticeExpenseReceiptUploads, postPracticeJournal, reversePracticeJournal, closePracticePeriod, reopenPracticePeriod, practiceLedger, firmTrialBalance, firmTrialBalanceAccount, issueInvoice, recordInvoicePayment, issueInvoiceReceipt, voidInvoice, listInvoices, calculateContractContribution, validateContractContribution, ensurePracticeRateDefaultsForFirm, listPracticeRateAdministration, schedulePracticeRateCard, assignPracticeStaffGrade, calculatePracticeChargeOutValue, recordAuthorizedPracticeTimeEntrySnapshot; `public.js` publishes scalar advance/final invoice evidence for workflow gates.
Published events: none yet.
Consumed events: none.
Allowed dependencies: platform services, shared browser-safe contracts, and the published `commercial/public.js` accepted-contract reader used to snapshot the exact issued letter/proposal.
Forbidden dependencies: another module internals or owned-table mutations.
State transitions: the CURRENT gate definitions are available; production transition commands are not implemented yet.
Critical invariants: explicit firm-wide grants, optimistic versions and durable command idempotency, same-firm composite foreign keys for period, account, expense, receipt, repository and reversal references, non-overlapping periods, draft-free reasoned period close, privileged reasoned period reopen, open-period reversal dates, approved posting policy, active posting accounts, PostgreSQL-balanced nonzero double entry, posted immutability, exact reversing entries, serialized line/posting/period-close races, decimal strings and append-only audit. Expense recognition drafts use the canonical balanced journal and open-period checks; the caller must select accounts. Operating expenses require an EXPENSE debit and ASSET or LIABILITY counterpart. Partner withdrawal requires an EQUITY or partner-current LIABILITY debit and ASSET counterpart and cannot be coded as an expense by choosing a UI category. Posting remains subject to approved firm policy and `PRACTICE_POST`. Receipt uploads require current firm-wide Practice authorization, size/type checks, ClamAV scan, private temporary storage, an explicit `practice-private` repository binding in production, exact provider version/hash pinning, idempotency, append-only audit and an immutable attachment row. They never fall back to client evidence or working-file repositories. PostgreSQL enforces same-firm expense/repository relationships and upload-session transitions; worker cleanup retries only bounded stale temporary objects. The tenant currently has no `practice-private` folder grant, so live Graph receipt acceptance remains pending; local RustFS and fake-Graph database acceptance are covered. Invoice issuance snapshots only the exact accepted proposal pinned by an issued letter, derives 50/50 amounts from the accepted contract using decimal half-even rounding, serializes a per-firm number sequence, and permits one active invoice per contract milestone. Issuance requires approved deferred-fee/no-tax firm policy, accounts 120 and 200, and an open period containing the issue date; the invoice, posted recognition journal and immutable link commit together. PostgreSQL validates exact debit/credit amounts, requires every invoice to have its link, and requires an exact posted journal reversal before an unpaid invoice can become VOID. Invoice issue/payment/receipt/void commands recheck current authority before replay and use PostgreSQL `OperationRequest` keys scoped by firm, client, engagement, actor, action and caller key; request hashes use canonical JSON, and operation result, business writes and audit commit together. Payments cannot exceed the remaining balance. Issued content, line snapshots, payments, receipts and void history are database-immutable; only an unpaid invoice with no payment can transition to VOID with a reason. Paid corrections require the not-yet-implemented credit-note workflow. Payment allocation/cash postings and AR aging remain open under later tasks. Other existing Practice journal commands still use durable `CommandReceipt` rows. Contract contribution reports unavailable rather than zero whenever a rate, currency or input is missing, and is never labelled payroll-cost profit (D07). Rate cards and staff grades are firm-scoped half-open effective-date ranges with non-overlap and versioned end-date closure; mutations require explicit `PRACTICE_MANAGE`, audit and idempotency. Time snapshots bind the staff member, engagement, effective grade and rate, preserve the applied hourly rate and half-even charge-out value, and are database-immutable. Job grade is independent of access role (D12).
