# WP07 — Establish the guarded lifecycle command pattern

Status: DONE for one guarded command family
Intent: Replace state-name advancement with named, evidence-checked commands that cannot be reached except through the permitted current state.
Source commit and files: `nirzaf/AuditSphere@64713e808d165b4ef91ea4be4979e0f98fb2def3`; `EngagementLifecycleService` and the acceptance/activation services in `Application/Security` and `Application/Acceptance`.
Destination commit and files: `packages/server/src/modules/governance/lifecycle.ts`, `packages/server/src/modules/governance/controller.ts`, `prisma/migrations/202610010007_lifecycle_history/migration.sql`, `apps/api/src/main.ts`.
Existing T-task links: T028 (guarded engagement transitions and state history), T063 (dual key) as the next family.
Dependencies: WP04 scope model (firm/client are read for evidence).
Scope: `START_FIELDWORK`, `SUBMIT_FOR_REVIEW` and `RETURN_FOR_REWORK`; each declares its permitted predecessor states and evidence predicate; the server derives the target state; history, audit and idempotency receipt commit with the state change.
Non-goals: A generic state-patch API, a workflow engine, and the full eleven-state command set.
Current behavior and invariants: `nextState()` remains available for presentation but is commented as unusable for authorization. No caller supplies a target state.
Proposed contract / schema change: `lifecycleCommandSchema` (command, expectedVersion, idempotencyKey, optional reason); `EngagementTransition` append-only history.
Permission and transaction boundary: guard requires engagement membership; the command locks the engagement row, rechecks the current state inside the transaction and writes version-guarded.
Historical data / document impact: none; the history is additive.
Implementation steps: as recorded in the migration, service and controller.
Relevant existing tests: `tests/invariants.test.ts`.
Minimal additional acceptance tests: missing evidence, invalid source state, unknown command, stale version, duplicate idempotency key with different content, and direct history/audit mutation.
Commands actually executed: `pnpm exec prisma migrate deploy`; `pnpm exec prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`; `pnpm build:server`; `pnpm contracts:generate`; `pnpm test:integration`.
Evidence and remaining blockers: `tests/lifecycle.integration.ts` passed against PostgreSQL 18.6, including that `START_FIELDWORK` is rejected from `FIELDWORK_EXECUTION` and that history/audit rows cannot be updated or deleted. Remaining: the other lifecycle states and the acceptance/dual-key evidence predicates are not implemented; authorization is membership-based until WP06.
Rollback / forward-recovery impact: additive; accepted transitions are history and must not be deleted.
Definition of done: met for this command family; remaining families are separate tasks.
