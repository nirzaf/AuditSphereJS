# WP08 — Immutable document-version and repository contract

Status: DONE for the binding/version contract (live tenant qualification remains MIG-012)
Intent: Replace one global drive/folder configuration and current-item eTag checks with a per-client repository binding and an immutable provider-version identity, so evidence cannot be written into a sibling client's site and an accepted version stays readable after the current item changes.
Source commit and files: `nirzaf/AuditSphere@64713e808d165b4ef91ea4be4979e0f98fb2def3`; `Documents/ClientSharePointSites`, `SharePointClientSiteProvider`, `Persistence/AuditSphereDbContext.ClientSharePointSites.cs`.
Destination commit and files: `packages/server/src/platform/graph-storage.ts`, `packages/server/src/platform/repository.ts`, `packages/server/src/platform/storage.ts`, `packages/server/src/modules/fieldwork/service.ts`, `packages/server/src/worker.ts`, `prisma/migrations/202610010010_client_repository_versions/migration.sql`.
Existing T-task links: T032 (storage metadata), T033 (upload pipeline), T034 (downloads), T064/T154 (SharePoint provisioning).
Dependencies: WP04 scope model; WP06 `TB_PUBLISH`-style capability checks are unrelated here but the same guard applies.
Scope: `ClientRepository` per (firm, client, purpose, provider); `DocumentVersion` capturing provider, drive, item, version id, eTag, SHA-256 and size; `resolveClientRepository`; Graph `put`/ `get` bound to a repository and reading the immutable version endpoint.
Non-goals: Replacing SharePoint with the local RustFS fixture; provisioning sites or consent (MIG-012); a live tenant permission review.
Current behavior and invariants: before this work the adapter used fixed configuration and failed a download when the current item's eTag changed. A reference now names a provider version, retrieval verifies that version's eTag and SHA-256, and a reference whose drive is not the client's binding is rejected.
Proposed contract / schema change: `ClientRepository` and `DocumentVersion` with check constraints and an append-only trigger; `GraphRepository` and `GraphReference` types; `storageProvider()` exported so the fieldwork path only resolves a binding when Graph is the provider.
Permission and transaction boundary: Graph credentials remain server-only and preauthenticated download URLs never receive the bearer token; retrieval is scoped to the owning client's repository.
Historical data / document impact: provider-scoped bytes are not rewritten; a new provider version becomes a new `DocumentVersion` row.
Implementation steps: as recorded in migration 202610010010, the adapter, the resolver and the two call sites.
Relevant existing tests: `tests/graph-storage.test.ts`.
Minimal additional acceptance tests: write routes to the bound repository; an accepted version is readable after the current item changes; substituted bytes, a tampered version eTag and a foreign-drive reference are rejected; a retired binding is ignored and production fails closed without a binding; version rows are append-only and constrained.
Commands actually executed: `pnpm exec prisma validate`; `pnpm exec prisma migrate deploy`; `pnpm exec prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma --script`; `pnpm build:server`; `pnpm exec tsc -p tsconfig.tests.json --noEmit`; `pnpm test`; `pnpm test:integration`; `pnpm db:roles`; `pnpm db:seed`.
Evidence and remaining blockers: `tests/graph-storage.test.ts` and `tests/repository.integration.ts` passed. Remaining: no live Microsoft tenant operation was performed, so site bindings, exact permission revisions and provider retention behaviour stay **NOT_VERIFIED**; repository provisioning itself is MIG-012.
Rollback / forward-recovery impact: version identity is append-only evidence; recovery means pinning the provider version, never rewriting the row.
Definition of done: met for the binding and version contract; live provider qualification is a separate gate.
