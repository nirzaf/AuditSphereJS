**Status:** Approved for implementation planning under the repository owner's existing delegation to Codex for implementation defaults (2026-10-08). ## Rule for removing a preparation form

A preparation form may be replaced only in the same reviewed task change that delivers its server-backed workflow. The owning task must persist the canonical records listed below, enforce engagement/firm scope and role authorization in the domain service, use optimistic versions and audit append-only decisions, expose the matching contract and UI, add a `pnpm verify:task -- T###` recipe, and pass the affected checks. A connected screen must render server state as authoritative and must not claim a mutation succeeded until the server confirms it.

Until those conditions pass review, keep the visible “Session-only preparation; persistence and execution pending” label. Drafts must stay in browser memory or explicitly session-scoped client state; they must not call mutating APIs, send communications, create approvals, bill, sign, release or archive. Never remove the label merely because the form looks complete.

## Review and accounting for partial delivery

This map was generated from the current workspace inventory and task cards on 2026-10-08. A task may own only part of a workspace. If a workspace spans tasks, connect only the completed server-backed subsection and retain a clear pending label on the rest. Update `docs/evidence/UI-MODULES.md` from the workspace table after each accepted connection; do not infer completion from an API service existing without an integrated screen and browser test.

The present inventory remains **25 session-only workspaces**. This guideline does not close their tasks, change the UI count, authorize external communications, approve methodology, or establish product acceptance.
