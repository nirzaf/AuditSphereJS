## Implementation checklist

- [x] Wire the approved Authorization Code/PKCE browser flow and API resource scope from the typed identity-configuration endpoint; verify the browser requests that exact scope.
- [x] Validate tokens at the API independently of browser MSAL, including signature, issuer, audience, expiry, tenant and delegated API scope; bind tenant and immutable subject identifiers.
- [x] Map staff to active local users by immutable tenant/object IDs and require local engagement membership plus a current scoped grant; unknown, inactive or unapproved tenant identities are denied.
- [x] Test expiry, logout/session revocation, user disable, scoped role ceilings and synthetic directory-administrator claims; no external directory role creates partner authority.

## Acceptance criteria and required tests

- [x] **AC1:** Signed-token tests reject Graph/wrong-audience tokens and wrong issuer, tenant, scope, expiry and malformed credentials.
- [x] **AC2:** Only configured-tenant immutable identity mappings to active local users authenticate; PostgreSQL/Fastify tests require local engagement membership and explicit scoped grants, and deny foreign/unassigned access.
- [x] **AC3:** Synthetic `wids`/`roles` administrator claims are omitted from the validated identity context; authorization tests prove local `ADMIN` cannot inherit APPROVER/partner capability even with an APPROVER membership and grants.

Exact SDK and peer evidence is in T150. Existing credentialed nonproduction Staff Fixture sign-in and bounded engagement acceptance are recorded in T019; this task changes no tenant settings or permissions. No credentialed action is needed for the API's negative token tests.
