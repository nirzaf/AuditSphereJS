# Direct libraries, services and conditional dependencies

Every proposed direct library and service is registered below. This is a selection/review register, **not an instruction to install every optional package**. Required capabilities may be met by built-ins or one selected provider. All exact versions, licenses, transitive vulnerabilities, engines, peers and target-platform requirements must be resolved in T005 and exercised in T017 or the named provider gate.

No library is approved solely because this table names it. State defaults to `DOCUMENTATION_REVIEWED / INSTALLATION_PENDING` for reviewed candidates and `SELECTION_PENDING` for unresolved helpers/providers. Native binaries and external service licensing are part of production compatibility. Registry access/installation was not available during pack generation.

## Evidence to record for every installed direct dependency

Package name; selected exact version; published engine and peer ranges; source/tag URL; license and usage approval; direct/transitive advisory results; target runtime/OS/CPU; lockfile integrity; required install script; owner; test name; actual result; decision date. Use [the evidence template](../templates/compatibility-evidence.md).

## Do not add by default

Express, Multer for Express, a second ORM, both class-validator and Zod for the same contracts, multiple data grids, a global state framework, multiple PDF engines, Redis cache eviction on the queue instance, Kafka, a CQRS framework, event sourcing, a second database, or a heavyweight monorepo scheduler. A need must be demonstrated and its package entered into this register first.

## Important selection details

Use the Angular-generated builder dependencies rather than forcing an arbitrary global Vite/Vitest version. Select one client generation path, not two manual/automatic model sets. ESM path exports and dependency injection must work in production output. Password hash and SWC native binaries must install on the target CPU/libc. PDF browsers need approved fonts and operating-system libraries. Keep signing material out of application images. S3-compatible APIs do not automatically imply equivalent records-retention guarantees. These are required project checks, not assumptions.
